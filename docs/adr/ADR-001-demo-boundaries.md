# ADR-001 演示边界：合成数据 + dry-run + 人工审批

- **日期**: 2026-11-23
- **状态**: proposed（随 SPEC 一起等待批准）
- **关联**: `SPEC.md` / Non-goals

## 背景

这是一个用于展示 LangGraph 多智能体、RAG 与 HITL 的演示项目。如果直接接真实 Amazon 店铺，会立即引入 OAuth、限流、幂等、审计合规、误操作赔偿等问题，演示价值反而被基础设施吞掉。必须先把「演示能做什么、不能做什么」钉死，否则后续每个功能都会问「要不要顺便接真实 API」。

## 备选方案

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| A 合成数据 + dry-run + 人工审批 | 可复现、零外部账号、安全、评测稳定 | 不能证明真实 API 集成能力 | **采用** |
| B 直接接真实 SP-API / Ads API | 更接近生产 | 账号、密钥、限流、误写风险；演示不可复现 | 拒绝 |
| C 只做单 Agent + 假数据 | 最简单 | 展示不了多 Agent、HITL、RAG 与审批链路 | 拒绝 |

## 决定

演示只使用 `data/seed/` 种子数据；`executor` 只写 dry-run 审计；任何执行前必须经过 `interrupt_before=["executor"]` 的人工审批。

> **2026-11-24 修订**：种子数据改为真实公开数据（Amazon Reviews 2023，品牌匿名化）+ 模拟广告/库存/成本，见 `ADR-003`。本 ADR 的 dry-run 与审批边界不变；「只使用合成数据」一句被 ADR-003 取代。

## 理由

- 演示的核心是**编排与闸门**，不是 Amazon 集成细节。
- 数据可复现，golden eval 才能当回归闸门（合成数据可完全复现；真实公开数据用固定快照 + sha256 复现）。
- dry-run + 审批把「模型建议」和「真实副作用」隔开，符合本项目要展示的治理思路。

**何时重评**：需要验证真实店铺写入、OAuth 或生产级幂等时，另立项目或另写 ADR；不得在本仓库悄悄打开真实写接口。

## 影响

- 代码 / 目录：`agent/nodes/executor.py` 只允许 dry-run；`agent/graph.py` 保留 `interrupt_before`；`data/seed/**` 只读。
- 依赖 / 运维：无需 Amazon 账号；LLM 可选，关闭时走兜底。
- 迁移 / 回滚：若未来接真实 API，必须新增鉴权、幂等键、失败补偿与更严格的审批记录；本 ADR 标记为 superseded。
